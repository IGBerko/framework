# Плагины для Framework v1.0.0

В этом руководстве описана архитектура модулей, процесс создания, регистрации и публикации плагинов для **Framework**, а также интеграция со сторонними библиотеками через CDN.

## Введение в систему модулей

Framework поддерживает расширение своего функционала с помощью двух типов модулей:
1. **Плагины (`.framejs`)** — специализированные расширения, разработанные специально под Framework, которые используют метод `Framework.plugin` для установки и могут иметь зависимости.
2. **Сторонние библиотеки (`.js`)** — популярные внешние решения (например, *lodash*, *axios*), загружаемые из встроенного каталога или по внешним ссылкам.

Загрузка модулей на странице осуществляется декларативно с помощью HTML-тега `<frameplugins>`:
```html
<frameplugins src="framecloud/1.0/math, framecloud/lib/lodash"></frameplugins>
```

## Разработка собственного плагина

Каждый плагин представляет собой отдельный JavaScript-файл с расширением `.framejs`. Имя файла должно строго совпадать с именем, передаваемым в метод регистрации `Framework.plugin`.

### Шаблон плагина (`plugins/custom.framejs`)

```javascript
/**
 * Плагин "custom" для Framework v1.0.0
 */
Framework.plugin('custom', {
  version: '1.0.0',
  
  // Список зависимостей, которые автоматически загрузятся перед активацией плагина
  requires: [
    'framecloud/lib/lodash' // Пример зависимости от библиотеки из каталога
  ],
  
  // Метод установки, вызываемый Framework после успешной загрузки самого плагина и всех зависимостей
  async install(fw, def) {
    // Расширяем глобальный объект Framework вашим функционалом
    fw.custom = {
      greet(name) {
        // Доступ к зависимостям осуществляется через fw.libs
        const cleanName = fw.libs.lodash.capitalize(name.trim());
        return `Привет, ${cleanName}!`;
      },
      
      logVersion() {
        fw.Yozilla.log(`Плагин ${def.name} версии ${def.version} готов к работе.`);
      }
    };
  }
});
```

## Каталог встроенных библиотек

Framework содержит предустановленный список (каталог `LIBS`) проверенных сторонних библиотек, доступных по коротким путям `framecloud/lib/<имя>` через CDN (jsdelivr):

| Имя для подключения | Глобальный объект | Описание библиотеки |
| :--- | :--- | :--- |
| `lodash` | `_` | Утилиты для работы с массивами, объектами и строками. |
| `dayjs` | `dayjs` | Минималистичная библиотека для работы с датами и временем. |
| `axios` | `axios` | HTTP-клиент для браузера на основе Promise. |
| `chartjs` | `Chart` | Интерактивные графики и диаграммы для сайтов. |
| `marked` | `marked` | Быстрый компилятор и парсер Markdown в HTML. |
| `anime` | `anime` | Гибкая библиотека для анимации интерфейсов. |
| `confetti` | `confetti` | Эффект выстрела конфетти на canvas. |

### Как это работает под капотом:
1. Вы указываете короткий адрес: `<frameplugins src="framecloud/lib/axios"></frameplugins>`.
2. Framework проверяет, есть ли уже объект `window.axios`.
3. Если объекта нет, создается динамический скрипт и загружает код с CDN.
4. После загрузки библиотека дублируется в объект `Framework.libs.axios` для изоляции зависимостей в плагинах.

## Публикация и структура репозитория

Для корректной работы вашей инфраструктуры плагинов на удаленном сервере (или GitHub Pages), придерживайтесь следующей файловой структуры:

```text
@framework1.0/
├── frm.js                        # Ядро вашего фреймворка
└── plugins/
    ├── 📄 math.framejs              # Плагин математических утилит
    ├── 📄 storage.framejs           # Плагин для работы с LocalStorage/SessionStorage
    ├── 📄 http.framejs              # Плагин для асинхронных запросов
    └── 📄 custom.framejs            # Ваш собственный плагин
```

### Настройка CORS
Поскольку плагины загружаются динамически через создание тегов `<script>` на любых сторонних сайтах, использующих ваш фреймворк, **сервер хранения плагинов обязательно должен отдавать HTTP-заголовок**:
```http
Access-Control-Allow-Origin: *
```
Это позволит избежать политик блокировки кросс-доменных запросов (CORS) в браузерах пользователей.

## Интеграция с отладчиком Yozilla

Система плагинов полностью контролируется встроенным отладчиком **Yozilla**. При работе с модулями происходят следующие процессы:

1. **Логирование успешной инициализации:**  
   При успешном разборе файла, разрешении зависимостей и выполнении метода `install`, Yozilla выведет в консоль и внутренний журнал сообщение:  
   `🟢 Успешно подключен модуль <имя>`
   
2. **Перехват и отображение ошибок:**  
   Если файл не удалось скачать, в коде плагина присутствует синтаксическая ошибка, или метод `install` выбросил исключение — Yozilla заблокирует подключение, сгенерирует событие отказа и выведет критическое окно ошибки на экран:  
   `🔴 Модуль <имя> не смог подключиться из-за ошибки: <текст ошибки>`

3. **Событийная шина фреймворка:**  
   Разработчики могут подписываться на жизненный цикл модулей внутри своих приложений:
   ```javascript
   // Подписка на успешную готовность конкретного модуля
   Framework.on('module:ready', (name) => {
     if (name === 'custom') {
       Framework.custom.logVersion();
     }
   });

   // Подписка на сбой при загрузке
   Framework.on('module:fail', (name) => {
     console.error(`Критическая проблема с загрузкой ${name}`);
   });
   ```
